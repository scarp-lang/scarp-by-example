# Lesson-writing standard

Each runnable lesson needs:
- A short descriptive `.srp` filename with a two-digit numbered prefix (e.g. `01-example.srp`). Lesson numbers in each chapter must start at `01`, be unique, and contain no gaps.
- A matching `.stdout` file with byte-exact printed output (UTF-8 and LF line endings; include trailing newline only if emitted). Intentional interior carriage-return bytes are allowed, but CRLF line endings are not.
- **Optional for input lessons:** A matching `.stdin` file (UTF-8, maximum 65,536 bytes). The verifier passes its bytes unchanged only to `scarp exec`; without one it supplies explicit EOF rather than inheriting an interactive terminal. Unlike stdout, both LF and CRLF are valid and meaningful stdin bytes. Orphaned, invalid-UTF-8 and oversized input fixtures are rejected. Add input-based lessons only after their syntax is supported by this course's pinned compiler. Explain the supplied input in the English/Hindi lesson notes; the current site does not yet show `.stdin` contents automatically.
- A section README table entry that explains the concept, includes the documented expected result, and links to the file.
- A matching numbered Hindi teaching section in `docs/hi/NN-topic.md` with the same original source and stdout links and a practical `**अभ्यास:**` question. The site publishes these notes directly on the standalone lesson page.
- A known upstream compiler reference and a successful compiler run before merge.

**Optional interactive checkpoint:** Curated quiz questions live in [`practice-questions.json`](practice-questions.json), not in `.srp` source or stdout fixtures. Each entry names an existing source file, an **exact line** from its compiler-verified stdout fixture (`evidence_line`), three bilingual answer options, the correct index, a bilingual question and an explanation. A build-time validator rejects missing translations, incorrect evidence lines, duplicate options and non-existent lessons. See [the checkpoint authoring standard](practice-checkpoints.md). The website displays these as comprehension checks only; it does not execute Scarp in the browser or record a score.

**Guided coding labs:** The standalone `labs/` catalog is separate from the numbered lesson examples. Each chapter lab has a compiler-valid `starter.srp`, a compiler-valid `solution.srp`, a byte-exact `solution.stdout`, and English/Hindi title, task, hint and explanation fields in [`guided-labs.json`](guided-labs.json). The starter must execute but not already equal the fixture; the solution must match exactly. See [the guided lab authoring guide](guided-labs.md). Optional `stretch` metadata may add four bilingual fields and a separate `stretch-starter.srp`, `stretch-solution.srp` and `stretch-solution.stdout` in the same lab folder. The verifier requires the stretch starter to execute but differ from its own fixture; it checks the stretch solution independently. Both core and stretch exercises are verified in CI on Linux, macOS and Windows, and neither inflates the 52-lesson count.

Avoid environment-dependent output, interactive prompts and speculative runtime features. Use the documented `scarp exec PATH` command and syntax supported by the pinned compiler commit. Both `print` and `println` appear in compiler-verified examples, but older prereleases may differ.

The verifier treats every `.srp` outside an `_support` directory as a lesson, requires one fixture per lesson, and fails on unmatched fixtures. All tested examples pass silent static `verify` and byte-for-byte `exec` output checks; legacy `check` semantics are tested separately. Read the [CLI guide](cli-quickstart.md) for command distinctions.
